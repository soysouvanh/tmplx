  <h1>Contenu injecté 0-allocation</h1>

Comportement du compilateur Tmplx

Les directives extends, block et include sont résolues de manière statique à la compilation pure.

Aucun overhead : L'arbre HTML complet est déroulé puis aplati sous forme de bytes dans le binaire Rust. Aucune recherche de fichier, ni allocation de tableau partiel n'a lieu au runtime. L'inclusion ne coûte littéralement que 0 ms en production.

Installation & configuration (zero to hero)

1. Initialisation Cargo

Ajoutez Tmplx au manifeste Cargo.toml.

Cargo.toml
[dependencies]
tmplx = "0.2.1"

[build-dependencies]
tmplx-compiler = "0.2.1"

2. Le compilateur (build.rs)

Placez ce fichier à la racine de votre projet. Il va parser vos templates à la compilation.

build.rs
fn main() {
    // Indique à Cargo de lancer le re-build UNIQUEMENT si le dossier 'templates' change.
    println!("cargo:rerun-if-changed=templates");

    // OUT_DIR est le dossier caché interne où le code Rust généré sera écrit.
    let out_dir = std::env::var("OUT_DIR").unwrap();
    let dest_path = std::path::PathBuf::from(out_dir).join("template_gen.rs");

    // Exécute le compilateur Tmplx. Tous les fichiers HTML deviennent des macros Rust.
    tmplx_compiler::build_workspace("templates", &dest_path);
}

3. Utilisation dans Rust

Vos macros 100% typées statiquement sont exposées ! Zéro lecture de fichier en prod !

src/main.rs
// A. On charge le code magiquement généré par notre build.rs
pub mod generated {
    include!(concat!(env!("OUT_DIR"), "/template_gen.rs"));
}

// B. La structure "Duck-typing" requise par la page ciblée (par ex. pour index.html)
struct MyViewData {
    title: String,
}

fn main() {
    // 1. Initialisation des données à afficher - variable my_view_data
    let my_view_data = MyViewData { title: "Tmplx".to_string() };

    // 2. Pré-allocation du buffer destination (html_output). Le moteur ne générera 0 allocation de lui-même !
    let mut html_output = String::with_capacity(4096);

    // 3. Appel final avec la macro. Tmplx pousse alors les variables et statiques dans 'html_output'.
    generated::render_index!(&mut html_output, &my_view_data);
}
